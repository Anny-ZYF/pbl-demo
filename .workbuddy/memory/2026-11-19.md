## 评分算法大改：paper-mcqs-v1 → smoothstep-v1（用户交付 1108.py + xgb_score_model4.joblib）

### 决策与公式
- 用户确认方向：替换规则分；实际组人数 `r` 从活跃链路移除（历史列保留）；模型覆盖 `p=1..4`；旧 XGBoost JSON 制品下架、保留 SHA-256 制品校验。
- 新规则 `smoothstep-v1`：`S(t)=3t²−2t³`，`a=1/p`；`x<=a` 时 `t=x·p, score=G·S(t)`；`x>a` 时 `t=(x−a)/(1−a), score=G+20·S(t)`；`clip(0,100)`。无 α 组规模系数、无 sin 基准分、无 p=4 仿射变换、不用 r。
- 模型：sklearn `XGBRegressor(n_estimators=150,max_depth=5,learning_rate=0.07,random_state=42)`，中文特征 `标准人数/个人贡献度/作业总分`，训练网格 40804 行（p∈1..4 × x 步长 0.01 × G 0..100）。
- 制品：`artifacts/score-model.joblib`（SHA-256 `a2b2c30a05b13b557748825f2d356c4563b1903edf4c53168c1bb46ee0e83644`），另四份 metadata/metrics/sha256/score-samples.csv。实测 holdout RMSE 0.8942731732 / MAE 0.6381276982 / R² 0.9992094930（真实计算，非编造）。
- 模型**拟合的是确定性规则网格**，不是真实评分数据；`joblib` 是 pickle 序列化，只加载仓库内已登记哈希的可信制品。

### 用户强调的边界

### 分工确认
- 根因之一：`ScoringMapper.studentWorkload` 用 INNER JOIN `workload_confirmation` 且不带 `group_id` 过滤；通过提交作业 `contributionScores` 生成的 LOCKED 版本没有确认记录，JOIN 会退回旧的 SUPERSEDED 版本 → 界面显示旧状态。改为 `JOIN group_member（按当前组） + LEFT JOIN confirmation`，取最新 `version_no`。
