# 教师端与学生端开发交接

本文档面向继续开发教师端、学生端的团队成员及其 AI 助手。当前管理员端是视觉和工程基线；教师端、学生端只有路由、统一布局和占位页，业务页面仍属于团队后续。

开始前依次阅读：

1. 根目录 `AGENTS.md`
2. [SYSTEM_DESIGN.md](./SYSTEM_DESIGN.md)
3. [API_CONTRACT.md](./API_CONTRACT.md)
4. [SCORING_ALGORITHM.md](./SCORING_ALGORITHM.md)
5. [DEPLOYMENT.md](./DEPLOYMENT.md)

## 1. 不可破坏的基线

- API 前缀固定为 `/api/v1`，统一响应由 `frontend/src/api/response.js` 解包。
- JWT 由 `frontend/src/stores/auth.js` 和 `frontend/src/utils/session.js` 统一管理，不按角色再造三套 Token。
- 前端角色统一为 `ROLE_ADMIN`、`ROLE_TEACHER`、`ROLE_STUDENT`；后端响应可为不带前缀的角色，使用现有工具标准化。
- 401 必须清理会话并回登录页；403 要显示无权限，不得伪装成空数据。
- `mustChangePassword=true` 时必须进入 `/change-password`；除读取本人、改密和退出外，后端也会拒绝其他业务接口。改密成功后清会话并用新密码重登，不得在前端绕过。
- 评分公式只在后端和算法服务实现。前端只能展示后端返回的贡献度、规则分、模型分、最终分和解释。
- 任何人工改分、发布或申诉处理都必须走现有 API，不能直接写数据库。
- 教师/学生账号删除是逻辑删除（`V8` 迁移的 `deleted_at` + `#<id>` 占位登录名），禁止为「删干净」而物理删除账号行或级联删除教学/成绩数据；所有账号查询都要排除 `deleted_at IS NOT NULL` 的行。
- 组织（院系/专业/班级）删除是物理删除，但必须先校验成员、子节点与课程/小组引用；前端隐藏按钮不能替代服务端校验。
- 教师只能访问自己课程和作业的数据；学生只能访问自己的选课、团队、工作量、成绩和申诉。
- 保持当前管理员端的简约视觉：浅色背景、内容卡片、清楚的页面标题、少量主操作、表格/表单优先。不要引入另一套 UI 框架。

```text
│  ├─ workload/             # W/Q 表格、合计提示、确认状态
│  └─ ...                   # 可复用小组件
```

## 3. 开发顺序

### 阶段 0：环境与契约冒烟

完成以下动作后再写页面：

1. 按部署文档启动 MySQL、Spring Boot、可选算法服务和 Vite。
2. 分别用管理员、教师、学生账号调用 `/auth/login` 和 `/auth/me`。
3. 确认教师访问 `/admin/dashboard` 为 403，学生访问 `/teacher/courses` 为 403。
4. 用 Swagger 或 HTTP 客户端读取将要开发的接口，记录真实响应字段。
5. 如页面所需字段不在接口中，先提交后端接口变更，不要先造假字段。

### 阶段 1：共享外壳

- 为 `RoleLayout.vue` 增加教师、学生各自的最小菜单。
- 保留账号菜单、修改密码、退出和移动端折叠。
- 每个角色仅注册自己的路由；路由 `meta.roles` 必须正确。
- 建立统一的加载、错误、空状态和分页用法。
- 不新增全局状态，除非两个以上无父子关系页面需要共享且刷新策略已明确。

验收：直接输入其他角色 URL 会被路由守卫重定向；后端仍会拒绝越权请求。

### 阶段 2：教师端基础教学

按以下顺序实现：

1. **我的课程**：调用 `GET /teacher/courses`。
2. **课程作业**：调用列表、创建、发布接口；创建表单必须校验截止时间、`p=1..4`、总分和分支权重。
3. **团队管理**：调用 `GET /teacher/courses/{courseId}/students?assignmentId=...` 获取候选人，调用 `GET /teacher/assignments/{assignmentId}/groups/{groupId}/members` 获取成员；建组人数不得超过 `p+1`。
4. **提交与团队评分**：提交列表已返回 `content/filePath/note`（过滤 `DRAFT`）；附件通过受鉴权 `GET /files?key=...` 下载，再录入 `groupScore` 和评语。未提交的草稿附件只对小组成员可见。

阶段验收：教师 A 不能读取教师 B 的课程、作业、团队或提交；权重和不为 1 的作业不能创建；非草稿作业不能重复发布。

### 阶段 3：学生端基础教学

按以下顺序实现：

1. **我的课程与作业**：只展示有效选课及已发布/结束态作业。
2. **我的团队**：补齐团队成员详情接口后展示成员和组长。
3. **团队作品提交**：**仅组长**可编辑并提交。**当前版本前端暂时移除了附件上传入口**：学生端只能填写「选题题目」文本并提交，不能再上传或移除附件；后端上传/登记/删除接口与历史附件数据全部保留，历史附件在提交卡片和已截止/已批改页面仍可查看下载，教师端批改页也照常可下载，恢复功能时把上传 UI 接回即可。界面上只有一个「选题题目」输入框，内容为空时无法提交（后端仅要求「说明或附件至少一项」，附件型历史提交重新提交时无需重传）。说明即提交内容，前端同时写入 `content` 与 `note`，教师端读到的是同一段文本。**工作量分工不在提交表单里**：组长在作业详情上方的「小组与工作量分配」中单独保存，**但提交前必须先保存**——本组该作业没有 `LOCKED` 分工版本时，提交卡片顶部显示红色提示「贡献度尚未填写」，点击「提交作业」只弹该提示并滚动到分工卡片，后端同样返回 400「请先在「小组分工」中填写并保存贡献度，再提交作业」。保存过分工后再提交即互不依赖（见阶段 4）。提交是小组级资源（唯一键 `assignment_id+group_id+is_latest`），组长提交后全组状态与内容同步；`DRAFT` 不算已提交，`scorePublished` 按本组判定。

**时间窗口**：不设学生组队期。作业发布后到 `deadline` 之前，建组/加入/退出、分工保存、附件与提交全部开放，学生一加入队伍即可由组长填写分工并提交作业；到 `deadline` 学生端所有写操作统一返回 409。`teamFormation` 字段恒为 `false`，仅为兼容保留，前端不要再用 `publishedAt + 2 天` 推算「组队中」。

**按组号快速加入**：学生端「或加入已有小组」列表提供组号搜索框（前端工具 `frontend/src/utils/groupSearch.js`）。纯数字按组号前缀匹配，输入 `1` 会列出第1组、第10组、第11组…，精确组号排在最前并高亮；`07` 等价 `7`；也支持输入完整组名（如「第10组」）。组名格式为「第N组」，后端 `studentAssignmentGroups` 已从 `g.name` 解析出 `groupNo`，无需改接口。**每张小组卡片同时显示组长姓名，格式为「第1组 | 演示学生01」**：`leaderName` 由 `group_table.leader_student_id` 关联 `student_users.name` 得到，缺失时回退到 `group_member` 中 `role='LEADER'` 的有效成员；组长退出时后端会把 `leader_student_id` 转给下一位成员，因此显示始终是现任组长。搜索词在加入/创建/退出小组成功后及切换作业时自动清空；没有匹配项时给出文字提示，不应显示成「暂无可加入的小组」。

阶段验收：非团队成员不能提交；**提交前必须先保存贡献度**（本组该作业存在 `LOCKED` 分工版本，否则后端返回 400、前端提交卡片标红提示）；发布后立即（不等 2 天）加入小组即可提交；截止后返回冲突时显示明确原因；重复提交更新同一团队作业的最新提交，不在前端制造重复记录。

### 阶段 4：小组分工（独立保存，保存即锁定）

学生端：

- 作业详情中有独立的「小组与工作量分配」卡片：按「评价分支 × 成员」矩阵填写份额，每个分支实时显示剩余可分配，全部为 100 才允许保存。
- **输入自动钳位（clamp）**：一个分支一行，总额上限 100 个百分点，先填的成员先占额度，后面的成员最多只能填「100 − 同行其他成员合计」。填 `140` 自动变 `100`；A 填满 `100` 后 B/C/D 输入任何正数都被钳成 `0`；把 A 改小后其余成员额度随之恢复。逻辑在 `frontend/src/utils/workload.js` 的 `clampCellValue` / `cellLimit`，回填历史数据时同样逐格钳位，因此提交给后端的份额永远合法。
- 仅组长可编辑；组员看到只读矩阵和实时加权贡献 `C`，没有确认/异议按钮。
- 保存即生成 `LOCKED` 版本并用于评分；可反复保存，新版本生成时旧版本自动 `SUPERSEDED`。截止后或小组被批改后不可再改。
- 与作业提交的关系：**分工必须先保存**（未保存时提交被拦截，见阶段 3）；除此之外两步互不耦合，可反复修改分工后再次提交。

教师端：

- 用同一矩阵查看或补录分工，每个分支合计须为 100；保存后立即 `LOCKED`，未发布成绩前可再次保存生成新版本。

阶段验收：保存后 `workload_set.status='LOCKED'`、`locked_at` 已写入，评分直接采用最新版本；不存在「等待全员确认」状态，学生端无确认/异议入口。旧版 `PENDING_CONFIRMATION` 数据仍可由截止清扫自动锁定。

### 阶段 5：评分复核与发布

教师端评分页最少展示：

- 学生、贡献度 `contribution`
- 团队作品分 `groupScore`
- 规则分 `ruleScore`
- 模型分 `modelScore`（可能为空）
- 模型—规则偏差 `modelRuleDelta`
- 异常标记 `anomaly`
- 建议/当前最终分 `finalScore`
- `explanation` 中的规则版本、分支、阈值、贡献度、归一化贡献度、加分上限、分数范围、模式和模型说明

交互规则：

- 教师保存团队成绩时自动按分工比例运行一次评分，个人成绩立刻出现在「成绩查看」，不需要再单独触发评分；页面上的「重新运行评分」只用于补录分工后重算。
- 小组从未保存分工时按组内均分计算（`contributionSource=equal_split`），保存结果的提示和成绩页要说明这一点，不能静默当成真实分工。
- `mode=model`、`rule_fallback` 要用中性、可理解的文案，不把回退渲染为系统崩溃；不再有 `rule_only` 模式。
- `anomaly=true` 要突出，但不能自动否决结果。
- 本次运行每名成员都必须提交复核决定。
- 最终分与当前建议分不同超过后端容差时，调整原因必填。
- 只有运行变为 `APPROVED` 后才显示发布动作。
- 发布需二次确认，说明发布后学生可见并开始 7 天申诉期。

阶段验收：未复核全员不能批准；批准前不能发布；学生在发布前看不到结果；发布后显示的最终分与教师复核一致。

### 阶段 6：成绩解释与申诉

学生成绩页：

- 默认突出教师最终分，同时把团队分、贡献度、规则分、模型分分区展示。
- 模型分为空时显示“本次采用规则评分”，不能显示 0。
- 解释面板只翻译后端字段，不在浏览器复算公式。
- 申诉按钮根据 `publishedAt + 7 天` 显示可用状态；最终是否超期仍以后端响应为准。

教师申诉页：

- 展示学生、作业、理由、证据、提交时间和当前状态。
- 只允许 `ACCEPTED` 或 `REJECTED`。
- 接受时调整后分数必填且为 `0..100`；两种结论都必须填写处理说明。
- 处理后重新读取列表，不能只改本地状态。

阶段验收：同一成绩不能有两个未处理申诉；超期申诉返回 409；教师不能处理他人作业申诉；接受申诉后学生成绩反映调整值。

## 4. 可选后端增强项

教师课程学生候选名单、教师/学生团队成员详情、提交说明/附件字段、教师工作量详情、学生申诉列表和受鉴权文件下载均已实现，不得再用假数据代替。首版页面需要的后端闭环已经齐备，可选增强项为：

1. 教师/学生专用工作台聚合接口；当前可组合已有列表。
2. 文件内联预览、删除与保留期限治理；受鉴权下载已经可用。
3. 通知、导出、作业归档和更丰富的工作量版本时间线。

新增读取接口也必须做资源归属校验，不能只依赖前端传入的教师 ID 或学生 ID。

## 5. 前端实现规范

### API 与状态

- 只向页面返回解包后的 `data`，不要让页面重复判断 `code`。
- 接口参数名严格使用 Java DTO 的 camelCase。
- 分页统一使用 `{items,total,page,pageSize}`。
- 日期传 ISO 本地日期时间；展示统一走格式化工具。
- 金额/分数用数值输入并限制范围；份额内部使用 `0..1`，UI 可显示百分比但提交前必须除以 100。
- 后端状态值原样保存；中文标签由集中映射函数生成，不在各页面散落判断。
- 不吞掉 409。它通常表示状态已被其他人改变，提示后应重新加载数据。

### 表单与并发

- 提交按钮在请求期间禁用，防止重复提交。
- 删除、发布、停用、复核、申诉结论等重要动作需要二次确认。
- 收到成功响应后从服务器重新读取关键实体。
- 不用数组下标当业务主键；`scoreResultId`、`workloadSetId`、`runId` 必须来自接口。

### 可访问性与简约风格

- 表单有可见标签和错误提示；不能只依赖 placeholder。
- 键盘可操作所有主要动作；弹窗关闭后焦点回到触发按钮。
- 颜色不是状态的唯一表达方式，异常、回退和通过都需文字。
- 小屏下表单改为单列，核心操作不被横向表格完全遮挡。
- 一页只保留 1 个主要操作；次要操作使用文本按钮或更多菜单。

```powershell

Set-Location frontend
```

- [ ] 教师只看到自己的课程。
- [ ] 作业分支权重和不为 1 时无法提交。
- [ ] 标准组规模与团队人数限制和后端一致。
- [ ] 能完成建组、查看作品、录入团队分。
- [ ] 工作量矩阵包含全部分支和成员，每分支份额和为 1。

### 学生端验收

- [ ] 学生只看到自己的有效选课和团队。
- [ ] 只能查看已发布作业并在截止前提交；不再出现「组队中」或「组队期结束后才能提交」。
- [ ] 加入小组后，组长需先保存分工再提交选题题目；未保存分工时提交卡片标红提示且后端返回 400。
- [ ] 「加入已有小组」输入 `10` 时第10组排首位并高亮，输入 `1` 同时看到第1组与第10组，输入不存在的组号显示明确提示。

- [ ] 截止后建组、加入、退出和提交操作均被后端拒绝（附件接口同样拒绝，但学生端已无上传入口）。
- [ ] 组员提交作业、编辑分工均被拒绝（403），界面显示只读内容与分工矩阵；附件接口对组员同样 403。
- [ ] 选题题目为空时提交按钮禁用；前端不再提供附件上传入口，历史附件仍可下载。
- [ ] 分工矩阵存在未满 100 的分支时无法保存；保存后侧栏显示「已保存（第 N 版）」，可再次保存生成新版本。
- [ ] 未发布成绩不可见。
- [ ] 最终分与规则分、模型分的标签没有混淆。
- [ ] 模型分为空时不显示为 0。
- [ ] 7 天内可申诉，超期和重复未结申诉有明确提示。
- [ ] 能查看申诉处理结果（依赖待补接口）。

### 跨端闭环验收

- [ ] 管理员创建教师、学生账号，首次登录能修改密码。
- [ ] 管理员删除教师/学生账号后有二次确认，账号从列表与登录中消失，课程/分组/提交/成绩历史仍在；管理员账号无删除入口。
- [ ] 组织树显示实时关联人数，只有无成员且无课程/小组引用的院系、专业、班级能删除；有引用时返回 409 并说明原因。
- [ ] 新增学生账号时班级号只随**学院**联动、切换专业不清空；输入超出预置 1~30 的班号（如 31）能在该学院下自动建班，且同号班级在学院内唯一、与专业无关。
- [ ] 教师创建并发布含多个评价分支的作业。
- [ ] 教师建立团队，学生提交作品。
- [ ] 教师录入团队分；组长或教师保存分工后直接锁定，评分采用最新版本。
- [ ] `p=1..4` 分别验证模型可用与规则回退；确认所有分数落在 0–100，且请求不再携带 `actualGroupSize`。
- [ ] 偏差严格大于 2 才标记异常，等于 2 不标记。
- [ ] 教师复核、发布，学生查看解释并申诉，教师处理。
- [ ] 管理员能在评分运行、异常和审计中追踪上述关键动作。
- [ ] 关键请求的响应头和响应体包含同一个 `requestId` 语义链路。

## 7. AI 协作要求

给 AI 的任务应包含：目标角色、页面、对应 API、允许修改的目录和验收命令。推荐模板：

```text
只实现教师端“工作量分配”页面；允许修改 frontend/src/views/teacher、
frontend/src/components/workload、frontend/src/api/teacher.js 和路由。
严格使用 docs/API_CONTRACT.md 中的接口，不修改评分公式或后端状态。
完成后运行 npm test 与 npm run build，并报告实际结果。
```

AI 不能自行决定以下事项：

- 更改公式或异常阈值；
- 放宽角色/资源归属校验；
- 直接改生产数据库；
- 使用假数据掩盖接口缺口；
- 将模型建议自动发布为最终成绩；
- 宣称未运行的测试已通过。

## 8. 完成定义

一个页面只有同时满足以下条件才算完成：

1. 使用真实接口并覆盖成功、空数据、校验失败、401、403、404/409 和网络失败。
2. 路由与角色守卫正确，后端资源归属验证通过。
3. 页面字段、请求体和状态与 `API_CONTRACT.md` 一致。
4. 关键动作刷新服务器状态并有审计事件。
5. 响应式和键盘操作可用。
6. 已实际运行相关测试/构建，并在交接说明中记录结果。
7. 对新增接口或状态同步更新相关文档。
